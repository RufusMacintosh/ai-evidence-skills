# 设计取舍与实现证据

本项目把文献写作和售电签约分析拆为“工作流说明、结构化材料、确定性检查”三部分。初始代码与文档采用AI辅助开发；个人贡献应按实际需求定义、代码修改、评测和业务判断记录分别说明，不把生成代码等同于个人独立编码经历。

## 需求如何落实

| 需求与业务判断 | 已有实现证据 | 当前边界 |
| --- | --- | --- |
| 每篇文献有摘要原句佐证 | evidence-schema.md规定原文快照、引文和位置；verify_evidence.py匹配本地摘要文本 | 不联网验证来源，也不验证完整句界或语义支持 |
| 参考理由不超过10字 | 检查Unicode字符长度，含标点；测试拒绝11字理由 | 不是中文语义质量评分，去除首尾空白后计数 |
| 借鉴范文的论证方法 | review-with-evidence/SKILL.md区分范文观察、证据文献及期刊硬要求 | 尚无真实范文上的抽取评测 |
| 签约比例有正确口径 | 监管分子/分母独立于预测负荷输入；测试使用不同监管分母 | 规则口径来自传入记录，需要人工核验官方材料 |
| 识别总量覆盖掩盖分时错配 | 分别累计每时段缺口和超额；合成案例各为50MWh | 不包含预测误差、交易成本、结算及风险价值模型 |
| 缺少证据时保留未知 | 缺少适用规则返回pending_verification | 未建立完整冲突规则引擎 |
| 结果可以复核 | 标准库脚本、合成输入、单元测试、CLI输出与运行记录 | 合成案例不代表真实业务泛化能力 |

文件路径均位于skills/下对应skill的references/或scripts/，测试位于tests/test_tools.py。

## 数值定义

对同一时段t，预测负荷为L_t，合同净覆盖为C_t，单位统一为MWh：

- 敞口：L_t − C_t。
- 缺口：max(L_t − C_t, 0)。
- 超额：max(C_t − L_t, 0)。
- 总预测覆盖率：ΣC_t / ΣL_t；分母为零时返回null。

缺口和超额分别逐时段累计，不先净额相抵。监管比例另用传入的适用分子和分母计算，不能把上述预测覆盖率直接当作合规结果。负净合同头寸及实际时间区间匹配暂不支持。

## 为什么保留简单工具

文本组织与范文归纳适合交给模型；字段约束和算术使用确定性代码，便于复现错误。第一版不引入多Agent框架、向量数据库或优化求解器，因为目前没有足够材料和评测证明这些依赖能改善结果。

## 状态字段怎么解读

| 字段 | 仅能说明什么 |
| --- | --- |
| evidence.ok=true | 当前字段检查与本地文本匹配通过 |
| forecast_coverage_ratio=1 | 总预测负荷与合同覆盖电量相等 |
| matches_supplied_threshold | 按传入记录完成范围/日期检查和阈值算术 |
| verified=true | 调用者声明规则已经人工核验，脚本没有验证该声明 |
| pending_verification | 无法完成适用规则的记录检查，不能给合规结论 |

## 尚未验证的风险

来源伪造、OCR错误、短语被误当完整句、摘录与正文论点不相符、重复或重叠实际时间区间、负荷预测失准、官方规则版本冲突与极端浮点数溢出。现有测试未覆盖全部风险；不将“测试通过”表述为“生产可用”。
